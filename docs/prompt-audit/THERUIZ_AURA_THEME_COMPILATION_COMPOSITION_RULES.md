# THERUIZ AURA 内容主题业务与 Prompt 组合规则

## 1. 文档范围

本文记录 THERUIZ AURA 当前内容主题的业务定位、用户输入、业务字段、图片组合规则、Prompt 编译数据流、产品参考约束、视频脚本输出方式以及当前业务完成状态。

本文只描述当前已经存在的业务，不包含开发方案、迁移方案、优化建议或未来规划。

## 2. 当前业务定位

THERUIZ AURA 是面向品牌内容生产的 Prompt Builder。当前业务由三类输出组成：

1. 小红书内容文案；
2. 1、3、5、8 张图片对应的 Image2 Prompt；
3. 根据图片内容计划生成的 Seedance 2.5 10 秒或 15 秒视频脚本。

当前没有接入 Image2 或 Seedance Provider API。系统负责整理参考图、组合业务参数、生成 Prompt 或视频脚本，用户复制输出内容后，在外部网站手动上传参考图并手动执行生成。

当前执行链路为：

```text
用户上传产品参考图
→ 用户确认参考图用途
→ 用户选择内容主题与业务参数
→ 用户选择 1 / 3 / 5 / 8 张
→ 系统生成对应的小红书内容与逐图 Prompt
→ 系统可基于同一组图片计划生成 10s / 15s 视频脚本
→ 用户复制 Prompt 或脚本
→ 用户在外部 Image2 / Seedance 2.5 手动上传参考图
→ 用户在外部手动生成
```

## 4. 八个主题的业务内容

### 4.1 生活场景软种草

业务目标是形成真实买家生活记录，而不是广告棚拍。

当前内容从以下生活场景家族中组合：

- 出门准备；
- 通勤移动；
- 咖啡店或轻社交；
- 书店、展览等文化活动；
- 社区或街区生活；
- 短途出行。

人物状态以自然生活行为为主，包括出门、行走、停留、落座、起身、转身、查看整体穿搭和与同伴交流。产品通过正常穿着、承重、落步和生活行为进入画面。

同一组内容保持同一人物、同一产品和同一套核心穿搭。不同图片通过场景、动作、视线、身体方向和构图尺度形成区别。

### 4.2 产品开发幕后

业务目标是展示产品被观察、比较、记录和整理的过程。

当前内容包括：

- 工作台上的产品与样品；
- 手部整理或检查；
- 色卡、材料样片或开发记录的关系；
- 产品局部结构观察；
- 开发过程中的环境痕迹。

该主题只表达参考图已经能够证明的产品外观关系，不把场景道具或图片角色转化为未经确认的产品事实。

### 4.3 秋冬配色实验室

业务目标是说明产品如何进入秋冬衣橱和季节配色关系。

当前内容包括：

- 产品与秋冬色卡；
- 产品与服装颜色关系；
- 产品与不同材质表面的视觉关系；
- 秋冬人物穿搭；
- 秋冬城市或室内使用场景；
- 配色比较与开发记录。

服装来自当前秋冬衣橱体系，包括 Core Basics 与 AW26 Upgrade。人物图保持鞋履为商业视觉核心，服装承担季节、比例和配色支持作用。

### 4.4 穿搭解决方案

业务目标是回答产品如何与服装搭配，以及整体比例是否成立。

当前内容主要覆盖：

- 全身穿搭基准；
- 产品与裤脚、裙摆或下装长度的关系；
- 行走时的动态比例；
- 坐姿或停留时的穿着关系；
- 产品与服装色彩的关系；
- 局部搭配证据。

该主题的核心是搭配解释。人物、服装和产品保持连续，构图围绕全身比例、下半身关系和产品可见性展开。

### 4.5 材质工艺认知

业务目标是让用户看到参考图中已经存在的表面和结构关系。

当前内容包括：

- 产品完整结构；
- 表面区域与表面处理；
- 纹理过渡；
- 接缝关系；
- 边界与构造细节；
- 手部观察或整理过程。

在没有真实结构化材质事实时，Prompt 使用中性的 reference-bound preservation language，不把参考图角色自动解释为 leather、suede、mesh、canvas、knit 或 nubuck。

### 4.6 品牌审美观点

业务目标是通过内容选择表达品牌的审美立场。

当前内容包括：

- 克制的生活空间；
- 城市建筑和街区关系；
- 阅读、展览和文化活动；
- 衣橱与日常物件；
- 人物自然状态；
- 材质和光线形成的触感。

该主题不承担具体产品参数说明，产品和人物可以作为品牌审美语境的一部分出现。

### 4.7 上新活动转化

业务目标是用一组图片完成新品介绍、使用证明和购买考虑。

当前内容包括：

- 产品主证据；
- 人物上脚或上身证明；
- 通勤或生活使用证明；
- 产品局部细节；
- 开发或准备过程；
- 上新收尾画面。

同组内容从产品本身逐步扩展到实际使用，产品始终是主要商业信息。

### 4.8 棚内上新拍摄

业务目标是在统一棚景内系统展示人物、造型和产品。

当前内容包括：

- 全身正面基准；
- 三分之四人物；
- 侧面或回身；
- 横向或斜向走动；
- 下半身落步；
- 产品局部；
- 服装与产品的整体关系。

同组保持同一棚景、人物、服装、产品、光线和相近镜头档位。动作可以发生明显变化，但不切换到咖啡店、酒店、街道、家庭或幕后工作场景。

## 5. 用户输入字段

当前主题内容由以下用户输入共同决定。

| 字段 | 业务含义 | 在输出中的作用 |
|---|---|---|
| 内容主题 | 用户本次内容目的 | 决定主题卡片、叙事责任和场景范围 |
| 图片数量 | 1、3、5 或 8 张 | 决定输出卡片数量和组内叙事长度 |
| 季节 | 春、夏、秋、冬等 | 约束服装、场景、光线和环境状态 |
| 场景偏好 | 用户选择的生活或拍摄语境 | 参与具体场景选择和场景兼容判断 |
| 人物 | 年龄、身份、外观和人物状态 | 决定人物身份与组内连续性 |
| 服装 | 当前服装要求或系统服装组合 | 决定人物穿搭和产品搭配关系 |
| 城市或地点语境 | 内容发生的城市、街区或空间 | 决定环境语言和空间细节 |
| 补充要求 | 用户本次附加说明 | 作为当前任务约束进入对应卡片 Prompt |
| Brand Visual | THERUIZ AURA 品牌视觉 | 统一画面气质、光线、色彩和真实感 |
| 产品参考图 | 用户上传的产品依据 | 作为外观保护、覆盖和 Reference Plan 的依据 |
| 图片角色 | 用户对参考图用途的确认 | 决定参考图在外部生成时承担的证据角色 |
| 视频时长 | 10 秒或 15 秒 | 决定 Seedance 2.5 的时间结构 |

## 6. 主题卡片字段

每张图片在进入 Prompt 编译前都具有一组主题卡片字段。

| 字段 | 当前业务含义 |
|---|---|
| `id` | 卡片的稳定标识 |
| `name` | 用户可见的图片名称 |
| `purpose` | 该图片在整组内容中的业务责任 |
| `description` | 该图片要表达的内容摘要 |
| `imageType` | 全身、下半身、静物、材质、氛围或其他图片类型 |
| `scenePreference` | 当前卡片唯一的权威场景 |
| `composition` | 人物、产品和环境在画面中的构图关系 |
| `productEvidenceRole` | 当前卡片承担的产品证据责任 |
| `personMode` | 人物、仅手部或无人 |
| `garmentTypePreference` | 当前卡片对服装类型的要求 |
| `supportedSeasons` | 当前卡片可使用的季节范围 |
| `family` | 生活场景所属的场景家族 |
| `handheldPolicy` | 手机或手持物是否允许出现 |
| `weight` | 卡片在候选选择中的权重 |
| `extraRequirement` | 当前卡片的附加业务约束 |

这些字段共同定义一张图片。系统不会只替换地点名称而保留与地点冲突的图片目的、构图或动作。

## 7. 1、3、5、8 张的组合方式

### 7.1 一张

一张图承担当前主题最核心的业务责任。

| 主题类型 | 单张核心内容 |
|---|---|
| 生活场景 | 一个完整、可信的生活使用瞬间 |
| 穿搭解决方案 | 全身或核心比例基准 |
| 上新活动转化 | 产品主证据 |
| 棚内上新拍摄 | 全身棚拍基准 |
| 材质工艺认知 | 一个明确的参考图细节关系 |
| 品牌审美观点 | 一个完整表达品牌语境的画面 |

### 7.2 三张

三张形成一个最短完整内容组：

```text
第 1 张：建立人物、产品或主题语境
第 2 张：展示使用、动作或搭配关系
第 3 张：补充产品证据或完成内容收尾
```

三张之间保持同一人物、产品和核心服装，通过场景功能、动作、构图尺度和产品证据责任形成区别。

### 7.3 五张

五张形成完整内容叙事：

```text
第 1 张：主叙事或全组基准
第 2 张：使用动作
第 3 张：产品证据
第 4 张：环境、生活或搭配证明
第 5 张：细节、幕后、观点或收尾
```

五张覆盖全身、中景、下半身、产品局部或环境关系中的多个尺度，并分配不同主动作。

### 7.4 八张

八张形成完整系列内容：

```text
第 1 张：总基准
第 2 张：第一动态
第 3 张：第二视角
第 4 张：身体方向或空间变化
第 5 张：中近景产品证据
第 6 张：人物、服装与产品关系
第 7 张：正面或结构细节
第 8 张：侧面、使用状态或收尾证据
```

八张模式保持系列统一，同时扩大动作、角度、距离、产品证据和环境信息的覆盖。

## 8. 组级业务字段

系统在编译单张 Prompt 前先确定整组共享状态。

| 组级字段 | 当前业务含义 |
|---|---|
| Topic | 整组内容主题 |
| imageCount | 整组图片数量 |
| season | 整组季节 |
| model identity | 整组人物身份 |
| product truth | 整组产品事实边界 |
| locked outfit | 整组核心服装 |
| city / environment context | 整组城市和环境语境 |
| visual family | 整组视觉气质和镜头家族 |
| selected drafts | 本组实际使用的主题卡片 |
| recent outfit history | 用于避免连续批次重复的近期服装记录 |

组级字段确定后，每张卡片继承共享状态，再加入自己的场景、动作、构图和产品证据责任。

## 9. 人物与服装流转

### 9.1 人物身份

同一组人物图共享：

- 年龄范围；
- 人物身份；
- 面部和发型；
- 身体比例；
- 核心服装；
- 包袋和主要配饰；
- 产品参考。

首张人物图建立人物，后续人物图延续同一人物。不同图片允许改变表情、视线、身体方向、手部任务和动作。

### 9.2 服装选择

当前服装流转为：

```text
季节
→ 内容主题与全部人物场景
→ 当前衣橱候选
→ 排除不兼容服装
→ 参考上一组及近期服装记录
→ 选定本组 outfit
→ 写入 locked outfit
→ 全部人物卡继承
```

秋冬服装候选由 Core Basics 与 AW26 Upgrade 共同组成。AW26 包含稳定 outfit presets，也能与 Core Basics 形成受约束的组合。

当前组内服装不逐张重新抽取。连续生成不同内容组时，系统参考上一组和近期服装记录降低重复。

### 9.3 服装与产品关系

服装承担以下业务作用：

- 表达季节；
- 建立人物身份和使用场景；
- 支持产品颜色；
- 形成完整穿搭比例；
- 保持产品可见；
- 不遮挡核心产品证据。

同一套最多保留一个明显的时装元素。彩色鞋履出现时，服装整体回到相对中性的色彩关系。

## 10. 场景数据流

场景由主题卡片决定，`scenePreference` 是当前卡片唯一的权威地点。

```text
内容主题
→ 图片数量
→ 候选主题卡片
→ 季节和场景兼容过滤
→ 选定具体卡片
→ 读取 scenePreference
→ 将场景写入单张 Prompt
```

生活场景软种草从出门、通勤、社交、文化、社区和旅行等场景家族中选择。穿搭解决方案根据全身、动态、坐姿和局部证据选择场景。棚内上新拍摄固定在棚内语境。

同一张卡片只保留一个地点。与权威地点冲突的咖啡店、酒店、镜前、棚内、街道或家庭地点描述不会同时保留。

酒店及酒店房间场景当前已从主题场景内容中移除。

## 11. 动作数据流

每张人物卡只保留一个主动作或一个主要物体操作。

```text
卡片 purpose
→ personMode
→ 场景允许的动作候选
→ 排除同组已使用动作
→ 选择当前主动作
→ 写入身体方向、手部任务、视线和位移状态
```

动作差异由以下字段共同表达：

- action family；
- pose type；
- body orientation；
- movement state；
- hand task；
- gaze direction；
- facial expression；
- product evidence behavior。

人物卡不会在同一画面同时叠加走路、整理衣服、拿杯子、看手机等多个主动作。

非人物卡的主要操作包括样品摆放、色卡比较、边缘检查、结构观察、护理动作和不同产品视角。

## 12. 构图与 Visual Role

主题卡片会被映射到当前 Visual Role。

| Visual Role | 当前业务内容 |
|---|---|
| A1 | 日常全身或放松生活构图 |
| A2 | 城市过渡、入口、行走和空间深度 |
| A3 | 室内生活、人物与物件关系 |
| B3 | 棚内正面全身基准 |
| B4 | 棚内三分之四人物与完整造型 |
| C1 | 完整产品侧面结构证据 |
| C2 | 人体使用状态下的产品、服装和地面关系 |
| C3 | 产品静物与表面关系 |
| C4 | 表面、接缝和边界局部 |
| C5 | 俯视结构证据 |

Visual Role 控制构图、画面距离、人物状态、相机关系和产品证据方式。它不增加产品材质、颜色、鞋头、鞋底或后跟事实。

## 13. 产品参考图业务字段

用户上传的产品图片首先保留原始上传顺序，再由用户确认每张图片的参考角色。

当前参考角色包括：

- 完整产品参考；
- 颜色参考；
- 材质区域参考；
- 鞋头参考；
- 鞋底参考；
- 后跟参考；
- 其他结构或局部参考；
- 未分类。

参考图角色只证明：

- reference role；
- coverage；
- evidence binding；
- reference plan order。

参考图角色不证明系统已经识别出具体材质、颜色、鞋头形状、鞋底形式或后跟结构。

## 14. Product Truth 字段与当前值

| 字段 | 当前值或状态 | 当前业务含义 |
|---|---|---|
| `productTruthMode` | `reference_bound` | 产品以用户确认的参考图为外观依据 |
| `referenceEvidenceBound` | 参考覆盖完整时为 `true` | 参考角色和证据覆盖已经确认 |
| `referencePlanReady` | 参考覆盖完整时为 `true` | 已形成建议的外部参考图上传顺序 |
| `structuredFactsExtracted` | `false` | 当前没有真实视觉模型提取结构化事实 |
| `manualExecutionReady` | 参考覆盖完整时为 `true` | 用户可以复制 Prompt 并在外部手动执行 |
| `providerExecutionReady` | `false` | 当前没有 Provider API 执行能力 |
| `productionReady` | `false` | 当前没有形成自动 Provider 生产闭环 |
| `facts.*.value` | 未确认时为 `unknown` | 系统不把图片角色转换为具体产品事实 |

完整参考图证据下的当前状态为：

```text
productTruthMode: reference_bound
referenceEvidenceBound: true
referencePlanReady: true
structuredFactsExtracted: false
manualExecutionReady: true
providerExecutionReady: false
productionReady: false
```

## 15. Reference Plan 数据流

Reference Plan 是用户在外部 Image2 或 Seedance 2.5 手动上传图片时使用的建议顺序。

```text
originalUploadOrder
→ 用户确认每张图片角色
→ 计算角色覆盖
→ 排除 unclassified 图片
→ 形成 confirmed references
→ 按产品证据用途生成 referencePlan order
→ 在界面显示建议的外部上传顺序
```

`originalUploadOrder` 记录用户原始上传顺序。`referencePlan order` 记录建议的外部使用顺序。用户修改图片角色时，Reference Plan 可以变化，原始上传顺序保持不变。

Reference Plan 不是已经发送给 Provider 的请求记录。

## 16. 单张图片 Prompt 字段流

每张图片的最终 Prompt 由以下业务信息组合：

```text
产品参考与 Product Truth
→ 人物身份
→ 组内锁定服装
→ 当前卡片主动作
→ 当前卡片权威场景
→ 构图与 Visual Role
→ 相机与工作距离
→ 光线与季节状态
→ 组内连续性
→ THERUIZ AURA Brand Visual
→ Negative 约束
```

最终 Prompt 的内容分区顺序为：

```text
product
→ model
→ styling
→ action
→ scene
→ camera
→ lighting
→ continuity
→ brand
→ negative
```

产品参考位于前部，人物、服装和动作随后进入，场景和相机负责建立画面，品牌视觉统一画面气质，Negative 约束位于末端。

内部使用的 ID、confidence、diagnostics、readiness 字段不会进入用户复制的 Provider Prompt。

## 17. 相机与产品比例规则

当前相机规则保留各图片类型原本的构图目标。

普通低风险画面使用原图片类型的镜头策略。鞋履透视风险较高的画面使用更安全的焦段档位和对应的相机距离。同一组图片保持相近焦段档位，维持系列感。

产品比例保护同时依赖：

- 焦段；
- 相机距离；
- 相机高度；
- 人物动作；
- 足部与镜头的前后距离；
- 产品在画面中的位置；
- 地面接触和承重关系。

Prompt 保持参考图中的鞋型、颜色、表面区域、鞋底和整体比例，不使用近距离广角夸张产品。

## 18. C4 材质局部业务语义

C4 用于展示参考图中的表面、接缝、边界和构造细节。

当前中性表述为：

> Preserve the exact material zones, surface finish, texture transitions, stitching relationships, and construction details shown in the confirmed material references.

在 `reference_bound` 且没有真实结构化材质事实时，C4 不输出未经确认的 leather、suede、mesh、canvas、knit 或 nubuck。

具体材质名称只会来自已经进入 Product Truth 的明确事实，不由 `material_reference` 图片角色自动生成。

## 19. Image Prompt 到视频脚本的数据流

视频脚本继承当前图片内容组的业务语境。

```text
同一组 TeamPromptParams
→ 当前 Product Truth 与 Reference Plan
→ 已选主题卡片
→ 每张卡片的场景、人物、服装、动作和产品证据
→ SceneSpec
→ FilmSpec
→ Motion
→ Camera
→ Product Protection
→ Reference Mapping
→ Seedance 2.5 Manual Video Script
```

视频脚本不是在图片 Prompt 后附加运镜。它把图片卡片中的人物、产品、服装、场景和证据责任转换为有时间顺序的行为链。

## 20. Seedance 2.5 视频业务字段

| 字段 | 当前业务含义 |
|---|---|
| `SceneSpec` | 视频发生的场景、人物、产品和环境状态 |
| `FilmSpec` | 10 秒或 15 秒的时间段和叙事节奏 |
| `Motion` | 人物或产品在真实时间中的动作链 |
| `Camera` | 相机距离、移动、视角和产品比例控制 |
| `Product Protection` | 产品外形、颜色、结构、比例和物理接触保护 |
| `Reference Mapping` | 视频脚本如何使用当前已确认参考图 |

视频动作采用真实时间约 1x。人物完成正常速度的转身、起步、行走、停留、落座、起身或展示行为，不以慢动作、时间拉伸或长时间悬停作为主要表达。

## 21. 10 秒视频结构

10 秒使用独立三节奏：

```text
0–1.5s：建立人物、产品和场景
1.5–9.3s：完成连续真实动作并提供产品证据
9.3–10s：保留 0.7 秒清晰收尾
```

10 秒内容保持单一、完整的行为链。场景数量和动作数量受到时长约束，不把多张图片机械拼接成快速场景列表。

## 22. 15 秒视频结构

15 秒使用独立四节奏：

```text
0–2s：建立人物、产品和场景
2–8s：完成主要行为链
8–14.3s：形成独立产品证据阶段
14.3–15s：保留 0.7 秒清晰收尾
```

15 秒拥有独立的 Product Evidence beat。该阶段使用正常承重、移动、地面接触、穿着关系或产品操作展示产品，不是把 10 秒脚本整体放慢。

## 23. 逐图视频与主题视频

当前视频脚本有两种业务输出：

### 23.1 逐图视频

每张图片卡片分别生成一条 10 秒或 15 秒脚本。

每条脚本继承该图片的：

- 图片名称；
- 内容目的；
- 场景；
- 人物；
- 服装；
- 主动作；
- 产品证据责任；
- Product Truth；
- Reference Mapping。

### 23.2 主题视频

主题视频从整组图片计划中选择多个内容节点，形成一条连续视频。首尾内容保留主题建立和收尾责任，中间内容承担行为和产品证据。

生活场景软种草和穿搭解决方案的视频以连续生活行为或穿搭展示为主。棚内上新拍摄的视频以同一棚景中的走动、转身、落步和产品展示为主。

## 26. 当前业务边界

当前系统已经完成的是内容主题选择、参考图用途整理、图片组编排、Prompt 组合、视频脚本组合和复制输出。

当前系统没有执行以下业务：

- 自动识别具体产品材质、颜色或结构；
- 自动把参考图发送给 Image2；
- 自动把脚本发送给 Seedance 2.5；
- 自动生成图片或视频；
- 自动轮询生成结果；
- 自动完成 Provider QC；
- 自动保存外部生成资产；
- 自动重试失败的 Provider 请求。

因此，当前业务状态是：主题内容与手动生成材料已经进入实际使用流程，外部 Provider 生成闭环仍由用户手动完成。
