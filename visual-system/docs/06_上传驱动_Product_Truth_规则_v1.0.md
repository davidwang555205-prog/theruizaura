# THERUIZ AURA 上传驱动 Product Truth 规则 v1.0

> 阶段：Phase 2-C2  
> 状态：Approved  
> 核心原则：**产品是事实来源，不是视觉导演。**  
> 适用范围：THERUIZ AURA 当前实验及后续 BM 平台迁移。

---

# 一、本次修正解决什么问题

此前视觉系统中仍残留一种逻辑：

```text
先判断产品属于什么 SKU / 系列 / 风格
→ 再匹配人物年龄、场景、穿搭和视觉表达
```

这一逻辑会产生三个问题：

1. 系统对产品进行过度解释；
2. 同类产品容易被套入固定视觉模板；
3. 品牌视觉判断被产品分类牵着走。

从本版本起，正式改为：

```text
品牌视觉母体
+
用户当次上传的产品图片
+
内容用途
+
本张图片角色
→
系统自动生成品牌化内容
```

产品图片只负责说明：

> **本次产品真实长什么样。**

产品图片不负责决定：

- 模特年龄；
- 模特面貌；
- 场景类型；
- 穿搭风格；
- 品牌气质；
- 光线方向；
- 内容是否年轻或成熟。

# 二、前台用户最小操作

用户每次任务原则上只需要：

1. 上传一组当前产品图片；
2. 选择用途；
3. 可选填写一句特殊要求。

用途示例：

- 官方内容；
- 小红书；
- 朋友圈；
- 买家秀。

系统不得把以下专业判断重新交给用户：

- 人物年龄；
- 模特气质；
- 场景；
- 穿搭；
- 动作；
- 光线；
- 镜头；
- 产品露出比例；
- 图组角色；
- Prompt；
- 负面约束；
- QA 标准。

# 三、四类决策来源

| 决策层 | 唯一职责 | 可以决定 | 不可以决定 |
|---|---|---|---|
| 品牌视觉母体 | 定义品牌长期视觉身份 | 人物范围、气质、色彩、光线、材质、空间、构图边界 | 当前产品结构和颜色 |
| 当次上传图片 | 定义当前任务产品事实 | 鞋型、材质、颜色、比例、裁片、后跟、鞋带、工艺 | 模特年龄、场景、品牌调性 |
| 用途适配器 | 定义内容如何被使用 | 图组结构、制作感、图片比例、内容角色、渠道规格 | 重新定义品牌风格 |
| 系统编排层 | 在规则范围内完成自动选择 | 模特轮换、场景调用、穿搭、动作、镜头、避免重复 | 擅自修改品牌母体或产品事实 |

# 四、上传图片是当前任务唯一产品事实来源

## 4.1 不再依赖预设 SKU

系统可以保存产品名称用于：

- 任务管理；
- 文件归档；
- 历史结果检索；
- 品牌内部识别。

但不得因为产品名称或预设分类，自动推导：

- 适合年轻模特；
- 适合成熟模特；
- 适合咖啡馆；
- 适合旅行；
- 适合某种固定穿搭；
- 应该更活泼或更稳重。

即使系统认识 Cloud Dancer、Aire、Silver Romance 等名称，也必须以**当次上传图片**重新建立本次 Product Truth。

## 4.2 不使用产品分类做视觉匹配

以下逻辑正式禁止：

```text
白鞋 → 通勤女性
银色鞋 → 年轻女性
麂皮鞋 → 秋冬咖啡馆
网面鞋 → 夏日户外
彩色鞋 → 更年轻模特
```

这些可以是人工经验，但不能成为自动生成的硬路由。

正确逻辑是：

```text
上传图片定义产品事实
品牌母体定义视觉身份
用途定义表达方式
系统在品牌范围内进行视觉编排
```

# 五、上传图片证据结构

用户上传的是“一组产品图片”，系统需要自动识别每张图片承担的证据角色。

## 5.1 核心证据角色

### A｜整体结构证据

用于判断：

- 完整轮廓；
- 鞋头宽度与形态；
- 鞋底厚度；
- 低帮比例；
- 整体长宽关系。

优先图片：

- 侧面图；
- 三分之四图；
- 完整单鞋或双鞋图。

### B｜俯视与前部结构证据

用于判断：

- 鞋头；
- 鞋带；
- 鞋舌；
- 鞋带孔；
- 前掌裁片；
- 鞋口。

### C｜后跟与侧面证据

用于判断：

- 后跟高度；
- 后跟裁片；
- 侧面条带；
- 鞋底与鞋面连接；
- 鞋口后部结构。

### D｜材质与工艺证据

用于判断：

- 皮革纹理；
- 麂皮绒面；
- 网布；
- 缝线；
- 包边；
- 鞋底材质；
- 金属或特殊表面效果。

### E｜上脚证据（可选）

用于判断：

- 鞋在真实脚部上的比例；
- 鞋口与脚踝关系；
- 上脚允许的自然形变；
- 鞋底接触地面的状态。

上脚图不能取代结构产品图。

# 六、上传最低要求与证据门禁

## 6.1 推荐最低上传组合

建议至少上传 3 张：

1. 一张完整侧面或三分之四图；
2. 一张俯视或正面图；
3. 一张后跟或材质细节图。

更完整的组合为 4—6 张。

## 6.2 证据不足时的处理

系统不得自行补全看不见的结构。

当证据不足时，只允许：

- 标记缺失的证据类型；
- 提示用户补传对应角度；
- 降低生成范围；
- 暂停无法保证真实性的图组角色。

提示应简单，例如：

> 当前图片无法确认后跟结构，请补充一张完整后侧或侧后方产品图。

不应让用户填写复杂结构表。

## 6.3 Product Truth 置信度

系统内部可分为：

- **High**：关键结构有多角度相互印证；
- **Medium**：主要结构可见，但部分细节只有单一证据；
- **Low**：结构被遮挡、分辨率低或缺少重要角度；
- **Blocked**：无法保证生成后仍是同一产品。

Low 或 Blocked 状态不得进入正式全图组生产。

# 七、允许推断与禁止推断

## 7.1 允许推断

只允许基于可见证据做保守判断，例如：

- 这是低帮鞋；
- 鞋底较薄；
- 鞋面主要是麂皮；
- 主色为低饱和紫色；
- 后跟存在白色皮革裁片。

## 7.2 禁止推断

禁止依据图片或名称擅自推断：

- 目标客户年龄；
- 价格带；
- 适用季节；
- 品牌想表达年轻或成熟；
- 产品属于通勤、旅行或约会；
- 产品应匹配何种场景；
- 产品应由什么人穿；
- 看不见的内部结构和工艺。

# 八、年龄系统修订

## 8.1 品牌人物范围

THERUIZ AURA 的视觉人物正式覆盖：

> **25—46 岁城市女性**

这是一项品牌级规则，不由产品决定。

## 8.2 年龄表达原则

25—46 岁所有人物共享同一个品牌母体：

- 有稳定审美；
- 温暖、克制、松弛、真实；
- 不少女化；
- 不网红化；
- 不幼态；
- 不刻意扮老；
- 不依赖职业模特姿态。

### 25—29 岁

允许更轻盈，但必须：

- 有轻熟感；
- 穿搭简洁；
- 动作自然；
- 不校园；
- 不甜妹；
- 不潮流堆叠。

### 30—39 岁

是品牌中最自然的城市生活表达层，但不是唯一主角。

### 40—46 岁

表达：

- 稳定；
- 自信；
- 松弛；
- 有生活经验；
- 不刻意塑造贵妇感。

## 8.3 年龄调用方式

年龄不得根据产品匹配。

系统应通过以下方式保持多样性：

- 从已批准的品牌模特池中轮换；
- 检查近期内容是否过度集中在同一年龄感；
- 同一图组保持同一人物身份；
- 跨任务维持 25—46 岁的自然覆盖；
- 用户无需每次选择年龄。

用途适配器也不得把某个渠道固定绑定某个年龄段。

# 九、产品弱化原则

“弱化产品”不等于产品不清楚，而是：

> 产品不再决定整个画面的世界。

## 9.1 视觉上

生活方式图中：

- 人物、空间和生活状态可以先被感知；
- 产品准确地参与画面；
- 不要求每张图都以鞋为最大主体；
- 产品可见度由本张图的角色决定。

产品图中：

- 产品仍然是主体；
- 但背景、光线、留白和材质表达必须继承品牌母体。

## 9.2 系统上

产品只影响：

- 产品结构保护；
- 颜色和材质还原；
- 参考图绑定；
- Product Truth QA；
- 某个镜头是否有足够证据生成。

产品不影响：

- 品牌人物；
- 品牌场景；
- 品牌价值观；
- 视觉年龄；
- 品牌色彩秩序；
- 品牌光线母体。

# 十、更新后的系统流程

```text
用户上传产品图片
→ 系统识别图片证据角色
→ 建立当前任务 Product Truth
→ 检查证据完整度
→ 调用 THERUIZ AURA 品牌视觉母体
→ 读取用户选择的用途
→ 编排图组角色
→ 自动选择模特、场景、穿搭、动作和镜头
→ 编译 Prompt 与参考图计划
→ 生成
→ Product Truth QA
→ 品牌一致性 QA
→ 用途与图组 QA
→ 交付
```

# 十一、系统内部最终公式

```text
品牌表达
=
品牌视觉母体
+
用途适配器
+
图组角色
+
系统多样性编排
```

```text
产品准确性
=
当次上传图片
+
当前任务 Product Truth
+
参考图计划
+
产品 QA
```

两条链路在生成阶段合并，但权限必须分开。

# 十二、本阶段冻结结论

从本版本起正式冻结：

1. 产品不再作为人物、场景和调性的匹配条件；
2. 当次上传图片是当前任务唯一产品事实来源；
3. 预设 SKU 只能用于管理，不能作为视觉路由；
4. 人物范围调整为 25—46 岁；
5. 年龄由品牌模特池和内容多样性管理，不由产品决定；
6. 用户仍只需要上传产品和选择用途；
7. 产品真实性与品牌表达使用两套独立判断链路；
8. Product Truth 证据不足时，系统只要求补图，不要求用户进行专业配置。
